Problem:
Vercel install fails with either npm or pnpm registry fetch errors, for example:

npm error Exit handler never called!
Error: Command "npm install" exited with 1

or:

ERR_PNPM_META_FETCH_FAIL GET https://registry.npmjs.org/...:
Value of "this" must be of type URLSearchParams

Cause:
The previous package contained a tracked package-lock.json and did not commit
pnpm-lock.yaml. Vercel detects package managers from lockfiles, so that can make
it choose npm or cache the wrong installer. Also, a vercel.json installCommand
override such as "pnpm install" can make Vercel use an older pnpm from the build
image instead of the version implied by the pnpm lockfile/Corepack.

Fix included:
- package-lock.json was removed from git.
- pnpm-lock.yaml was generated and should be committed.
- packageManager is set to pnpm@10.14.0.
- Node is pinned to 20.x for Vercel instead of an open-ended >=20 range.
- vercel.json no longer overrides installCommand.
- .gitignore blocks package-lock.json from being committed again.

After pushing this package:
1. Go to Vercel > Project > Deployments.
2. Redeploy.
3. Enable "Clear build cache" if Vercel still tries npm or an old pnpm.
4. Make sure Project Settings > Build & Development Settings does not override
   Install Command with npm install or pnpm install.
5. If Vercel still does not use packageManager, add project environment variable
   ENABLE_EXPERIMENTAL_COREPACK=1.
