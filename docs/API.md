# control-app API documentation

This document describes every public endpoint included in `control-app`.

## Common behavior

All API responses are JSON. API route handlers set `Cache-Control: no-store` on validation/control responses so the browser does not reuse access decisions.

## `POST /api/script/check`

Main endpoint used by the Tampermonkey userscript. It validates the license token, applies block rules, registers or updates the device, stores the account snapshot, and writes a script event.

### Request body

| Field | Type | Required | Description |
| --- | --- | --- | --- |
| `token` | `string \| null` | No | Raw license token assigned to the user. Missing tokens can still pass in `open` or `soft` mode. |
| `deviceId` | `string` | Yes | Browser/profile identifier generated by Tampermonkey and stored with `GM.setValue`. |
| `eventType` | `check \| heartbeat \| painted \| denied \| logout` | No | Event type. Defaults to `check`. |
| `scriptVersion` | `string \| null` | No | Userscript version. |
| `currentUrl` | `string \| null` | No | Current page URL where the script is running. |
| `storageKey` | `string \| null` | No | Informational label describing where the local token/device id is stored. |
| `accountToken` | `string \| null` | No | Optional raw account token supplied by your own flow. It is stored raw and hashed in this test build. |
| `account` | `object \| null` | No | Account profile snapshot. Unknown fields are kept in `raw_profile` except the raw base64 picture. |
| `metadata` | `object \| null` | No | Extra event metadata such as paint counts, target names, or debug notes. |

### Successful response

```json
{
  "allowed": true,
  "mode": "open",
  "ownerName": "Roberto",
  "username": "Gallardeus",
  "expiresAt": "2027-06-01T00:00:00+00:00",
  "registeredDevices": 1,
  "maxDevices": 10
}
```

### Blocked response

```json
{
  "allowed": false,
  "mode": "strict",
  "reason": "Device limit reached.",
  "registeredDevices": 10,
  "maxDevices": 10
}
```

## `POST /api/script/event`

Alias of `/api/script/check`. Use it when the call is conceptually an event, but the implementation is exactly the same.

## `POST /api/license/validate`

Validates only the license token. It does not register a device, update `last_seen_at`, write account snapshots, or insert script events.

### Request body

```json
{
  "token": "KGM-yYR8S1o5lHUzecKTE0HqEPx9Qdr81hEs"
}
```

### Valid response

```json
{
  "valid": true,
  "licenseId": "uuid",
  "ownerName": "Roberto",
  "username": "Gallardeus",
  "status": "active",
  "maxDevices": 10,
  "expiresAt": "2027-06-01T00:00:00+00:00"
}
```

### Invalid response

```json
{
  "valid": false,
  "reason": "invalid_token"
}
```

## `POST /api/licenses/validate`

Plural alias of `/api/license/validate`.

## `GET /api/admin/licenses`

Lists licenses and registered device counts. Requires `x-admin-key`.

```bash
curl https://control-app.vercel.app/api/admin/licenses \
  -H "x-admin-key: YOUR_ADMIN_API_KEY"
```

## `POST /api/admin/licenses`

Creates a license. Requires `x-admin-key`.

### Request body

| Field | Type | Required | Description |
| --- | --- | --- | --- |
| `ownerName` | `string` | Yes | Friendly owner name. |
| `username` | `string \| null` | No | Optional account username. |
| `token` | `string \| null` | No | Optional raw token. If omitted, the API generates one. |
| `maxDevices` | `number` | No | Maximum device count. Defaults to `10`. |
| `expiresAt` | `string \| null` | No | ISO expiration date. `null` means no expiration. Omitted means one year from creation. |

### Example

```bash
curl -X POST https://control-app.vercel.app/api/admin/licenses \
  -H "content-type: application/json" \
  -H "x-admin-key: YOUR_ADMIN_API_KEY" \
  -d '{"ownerName":"Friend 11","username":"friend_11","maxDevices":10}'
```

## `GET /api/admin/overview`

Returns recent license, account, and script event data for the tiny dashboard. Requires `x-admin-key`.

## `/admin?key=YOUR_ADMIN_API_KEY`

Minimal dashboard page that reads directly from Supabase server-side. It is fine for private testing. Replace it with a real auth flow if this becomes public.
